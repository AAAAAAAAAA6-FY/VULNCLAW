# VULNCLAW 扫描器缺陷清单与优化方向

> 生成时间：2026-09-01
> 依据：真实扫描（目标 https://httpbin.org，非危险模式）+ 全量语义审查 + 代码定位
> 分布要求：40% 复杂/0day 漏洞检测 · 20% 信息收集/覆盖率 · 20% 准确率提升 · 20% 速度提升
> 规模：20 大点 / 80 小点（A=32 / B=16 / C=16 / D=16，严格按 40/20/20/20 分布）

---

## 0. 本批次已修复缺陷（基线扫描挖出，均已验证）

| 缺陷 | 根因 | 修复提交 | 验证 |
|---|---|---|---|
| SPA 检测永久失效 + 协程泄漏 | `SpaFingerprintDetector` 被传入 aiohttp `ClientSession` 却用同步 `requests` 语义，`session.get()` 返回协程、`resp.status_code` 抛 AttributeError 被静默吞掉，未 await 协程 GC 时打 `RuntimeWarning: coroutine 'ClientSession._request' was never awaited` | `ea5e7e4` | httpbin 单测无警告，SPA 检测复活 |
| 主扫描 OOB 回退缺口 | `burp.py` `collaborator_generate` 只走 interactsh-client，挂掉即"跳过 OOB 检测"；而 verify 阶段 `OOBVerifier` 有 interactsh→dnslog→local 回退，主路径与 verify 行为不一致 | `1534d81` | interactsh 8s 超时后自动回退 dnslog，`OOB 通道就绪 (dnslog)` |
| Nuclei CVE 扫描全量废掉 | `thirdparty/tools.yaml` nuclei `default_args="-silent -json"`，但 nuclei v2.9.15 无 `-json` 旗标（正确 `-j`/`-jsonl`）→ 每次 `flag provided but not defined: -json` exit=2，扫描根本未执行 | `1534d81` | exit 2→0，模板更新成功，输出文件可正常 JSONL 解析 |

> OOB 自回调误报（引擎/verify 两处）此前已修：`d02aeff`、`1db53bb`。

## A. 复杂 / 0day 漏洞检测（40% — 8 大点 / 28 小点）

### A1. OOB 带外通道统一化与多协议回调证据链
**现状缺陷**：存在三套 OOB 实现（`core/oob_channel.py`、`ai/burp.py` collaborator、`core/exploit_verify.py` OOBVerifier），逻辑分散、行为不一致（主路径回退缺口本轮已修但仍未完全收敛）；interactsh 单点依赖公共服务器 `oast.me`，限流/不可用即整链降级；dnslog.cn 仅覆盖 DNS+HTTP，缺 LDAP/SMB 回调（JNDI/反序列化盲打的关键证据）。

**优化小点**：
1. 收敛为单一 `OOBChannel` API，删除 `burp`/`verify` 中的重复 OOB 逻辑，消除"三套实现行为漂移"。
2. 引入自部署 interactsh server 作为第二主通道，摆脱公共服务器限流与单点故障。
3. 增加 LDAP/RMI/SMB/SMTP 回调协议支持，覆盖 JNDI 注入与 Java/.NET 反序列化盲打。
4. 回调证据链持久化（token→interaction 落库），支持跨轮次复核、去重与事后审计。

### A2. 反序列化引擎（CWE-502）覆盖扩展
**现状缺陷**：`deserialization` 引擎已注册进 `global_engines`，但 payload 集有限、强依赖带外通道，多技术栈覆盖不足。

**优化小点**：
1. 扩充多栈 payload：Java（Fastjson/Jackson/SnakeYAML/XStream）、.NET（BinaryFormatter/LosFormatter/NetDataContractSerializer）、Python（pickle/pyyaml）、PHP（unserialize/Phar）。
2. gadget 链指纹库（对齐 ysoserial/marshalsec），带内回显探测优先（DNS/HTTP OOB 为兜底）。
3. Content-Type 嗅探驱动 payload 选择（`application/json` vs `x-java-serialized-object` vs `application/x-java-serialized-php`）。
4. OOB payload 与 A1 通道 token 绑定，按 token 精确判定实锤，避免串台回调。

### A3. SSTI 沙箱逃逸与多引擎 payload 矩阵
**现状缺陷**：`ssti` 引擎存在但方言覆盖与沙箱逃逸深度不足。

**优化小点**：
1. 引擎矩阵覆盖 Jinja2/Twig/Mako/Velocity/Freemarker/Thymeleaf/Handlebars/Smarty/Pebble 多方言。
2. 沙箱逃逸 payload 库（对齐 ppletrea），多态变形绕过黑名单。
3. 带内回显（数学运算结果比对）+ OOB 外联双判定，降低纯字符串匹配误报。
4. 上下文感知注入（参数位置/模板边界识别），减少破坏性 payload。

### A4. JNDI 注入家族（Log4Shell/Fastjson/Struts2/Spring）深度化
**现状缺陷**：框架类盲打引擎偏单点，gadget 与版本映射不细。

**优化小点**：
1. Log4Shell 多向量覆盖（HTTP header 全字段、User-Agent、`${}` 占位语法全变种）。
2. Fastjson 1.2.24/1.2.47/autotype 多版本 gadget 分版本触发。
3. Struts2 OGNL 系列（S2-001~S2-062）按指纹版本选择 payload，避免无效大爆破。
4. 全部接 A1 的 LDAP/RMI/DNS 回调 + 时间盲打兜底（目标无外联时）。

### A5. GraphQL 内省/越权/批量查询检测
**现状缺陷**：无独立 GraphQL 引擎，端点发现与越权检测缺失。

**优化小点**：
1. 端点发现（`/graphql`、`/graphiql`、常见别名）+ introspection 探测与禁用绕过。
2. 字段建议泄漏（suggestions）信息泄露判定。
3. 批量查询/嵌套深度（depth/complexity）DoS 与越权字段提取。
4. mutation 越权（alias-based IDOR）+ `__schema` 离线字典化复扫。

### A6. 原型链污染（prototype pollution）深度化
**现状缺陷**：`prototype_pollution` 引擎已注册但落地回显链薄弱。

**优化小点**：
1. JSON merge / query / param / header 多注入点全覆盖。
2. gadget 链落地回显（ejs/pug/nunjucks 模板 RPE），不止"注入即报"。
3. 服务端 merge 库指纹驱动（lodash.merge/extend、express-body-parser）。
4. 假阳性抑制：必须观察到副作用（如覆盖后渲染异常）而非仅返回 200。

### A7. WebSocket 安全检测引擎化
**现状缺陷**：`websocket_security` 引擎已加载，但帧级检测深度有限。

**优化小点**：
1. ws/wss 协议升级与消息帧抓取标准化。
2. Origin 校验缺失（CSWSH）自动探测。
3. 鉴权透传/越权消息（同一连接内身份切换）检测。
4. 反序列化消息体（JSON-RPC gadget）与帧拆分异常 fuzz。

### A8. 0day 情报驱动扫描（CVE 索引 + nuclei -id 精确命中 + PoC 库）
**现状缺陷**：`cve_index`（`thirdparty/nuclei-templates/cve_index`）已建、nuclei `-jsonl` 已修，但"指纹→CVE 候选→-id 精扫→PoC 复核"链路未闭环；情报源未接入。

**优化小点**：
1. 指纹→CPE/CVE 候选映射驱动 nuclei `-id` 精扫（替代大爆破 tags）。
2. `deepsec/poc_generator`（Jinja2）PoC 库与 CVE 双向索引，命中即生成复现命令。
3. 漏报率回归基线（已知 CVE 靶场命中率）持续监控。
4. 情报源接入（NVD/ExploitDB/GitHub monitoring）增量更新模板与 PoC。

## B. 信息收集与覆盖率（20% — 4 大点 / 14 小点）

### B9. 子域名多源融合与被动 DNS
**现状缺陷**：subfinder+assetfinder+crt.sh+OTX+urlscan 已并发，但 OTX 频发 429 限流、仅指数退避未做源级熔断；DNS 爆破字典静态。

**优化小点**：
1. 增加 Chaos/SecurityTrails/RapidDNS/Hackertarget 多源，降低单源依赖。
2. 429/限流指数退避 + 源级熔断（连续失败即短期摘源，避免拖慢整体）。
3. 主动 DNS 爆破字典进化（组织词/叠词/历史命中回灌）。
4. 证书 SAN 反查 + 泛解析/CNAME 收敛去重，避免假子域污染。

### B10. 目录/参数发现（ffuf + arjun + 字典进化）
**现状缺陷**：arjun 缺失降级（隐藏参数发现空转）；ffuf 字典静态、智能过滤弱；SPA 假 404 已有检测但未与 ffuf 联动。

**优化小点**：
1. arjun 自动补齐（setup 下载）或内置参数发现算法，填补隐藏参数盲区。
2. 字典自适应（按技术栈/响应词频进化，命中词加权复用）。
3. ffuf 智能过滤与 SPA 检测（C16）联动，自动校准假 200/假 404。
4. 参数发现融合（GET/POST/JSON/Header 多位置）+ 递归深度可配与早停。

### B11. JS 深度分析与端点/密钥提取
**现状缺陷**：JS 分析仅统计字符数、0 端点产出；未提取 API 路径/密钥/SourceMap。

**优化小点**：
1. AST/正则提取 API 路径（fetch/axios/相对 URL），回灌到扫描队列。
2. 密钥/令牌泄漏扫描（AKIA*/api_key/JWT/私钥），命中即告警。
3. SourceMap 还原原始源码，扩大提取面。
4. 第三方依赖版本指纹（CPE 关联 A8）+ 内嵌 GraphQL/REST schema 提取。

### B12. 端口/服务指纹与协议探测
**现状缺陷**：端口扫描仅 TCP 开放判定，服务版本/UDP/协议识别浅。

**优化小点**：
1. nmap-like 服务版本探测（banner 抓取），驱动 nuclei tags（P4-3 已有映射，增强闭环）。
2. UDP 关键端口（161 SNMP/123 NTP/1900 SSDP）探测。
3. 非标端口 HTTP 探测 + 协议识别（避免漏掉迁移端口的 Web 服务）。
4. 端口→漏洞直连（如 6379 Redis 未授权、27017 Mongo 未授权直接触发专项引擎）。

## C. 准确率提升（20% — 4 大点 / 14 小点）

### C13. 假阳性抑制（自回调/基线/double-fetch）
**现状缺陷**：本轮已修 OOB 自回调误报（引擎/verify 两处），但抑制策略未系统化、未覆盖所有带外引擎。

**优化小点**：
1. 自回调检测扩展至所有带外引擎（注册域名自身回环即弃，不限于 OOBVerifier）。
2. 基线响应指纹对比（status/长度/正文哈希）自动校准假 200/软 404。
3. double-fetch 确认（重复注入两 token，仅命中自身 token 才实锤）。
4. 时间窗约束（回调须在注入后 N 秒内）+ 误报回归集（httpbin/自建靶场，vulnweb 不可达）。

### C14. AI 判定与人工复核闭环（confidence 校准）
**现状缺陷**：V100 + ReAct 深挖已接线，但 confidence 阈值曾有误确认（已修），分级与回灌弱。

**优化小点**：
1. confidence 校准集（已知漏/已知净）训练阈值，避免固定值一刀切。
2. 分级输出（confirm/likely/suspicious）而非二值，降低人工筛选成本。
3. 人工复核队列 + 反馈回灌（clue_engine 记忆跨目标复用）。
4. ProviderFailover 多模型投票（glm/qwen/deepseek 一致才高置信）+ 误判样本可追溯（payload+响应+判定链落库）。

### C15. 双源确认（引擎 + Burp 独立确认）
**现状缺陷**：`cross_confirmed`/`burp_confirmed` 字段已有，但 Burp 常不可用致第二源空转。

**优化小点**：
1. Burp 缺失时第二源降级为 nuclei `-id` 重测（复用 A8 链路）。
2. 独立重放（不同 cookie/session）验证越权/IDOR 类，避免会话污染误判。
3. 跨引擎交叉（XSS 引擎命中 + DOM 渲染器确认）+ 结果落 `confirmation_sources`。
4. 仅双源一致才标 Critical，单源自动降级，减少"实锤假阳性"。

### C16. SPA/动态渲染识别避免假 404
**现状缺陷**：SPA 检测本轮刚修复（`ea5e7e4`），但仅首页指纹对比、无 Headless 渲染。

**优化小点**：
1. 多路径指纹（不止首页）+ 状态码模式聚类，提升 SPA 判定准确度。
2. Headless 渲染（Playwright）对 JS 重路由判定真实可达，识别假 404。
3. 软 404（200 但内容为错误页）识别 + 假 404 字典扫描期累计自动剔除。
4. 与 ffuf 联动自动校准匹配过滤（B10 联动）。

## D. 速度提升（20% — 4 大点 / 14 小点）

### D17. 自适应限流与并发调度
**现状缺陷**：`AdaptiveRateLimiter` 已有（保护模式 8 QPS），但仅 429 信号调速、冷启动与降级恢复粗糙。

**优化小点**：
1. 响应延迟/429/超时三信号联合调速（非仅 429），更早感知目标压力。
2. 冷启动渐进爬坡（避免首秒冲爆触发封禁）+ 按目标分组限流（多目标不互相饿死）。
3. 优先级队列（CVE/高信引擎先跑）+ 降级冷却（60s）可配且并发恢复阶梯。
4. 全局任务预算（max_tasks 已有，增 token/时间预算早停）。

### D18. 异步 IO / 共享会话复用
**现状缺陷**：`get_shared_session` 已复用 aiohttp；但仍有 sync `requests` 调用阻塞 loop（spa_detector 本轮已修，需全量审计）。

**优化小点**：
1. 全量审计 sync `requests` 调用 → 转 aiohttp（spa_detector 已示范修复模式）。
2. 连接池调优（per-host 限制、keepalive）+ DNS 缓存（aiohttp DNS resolver）。
3. 超时分层（connect/read/total 分别设）+ HTTP/2 多路复用（`--http2` 默认评估启用）。
4. 请求重试与熔断（连接错误指数退避 + 单目标连续失败即短期熔断，避免拖慢批次）。

### D19. 工具并行化与 DAG 调度
**现状缺陷**：深度侦察并发组1（1-7 步）已并行；DAG 模式可选但失败重试/死信（P1-3 待办）未落地。

**优化小点**：
1. 引擎按依赖拓扑调度（recon→attack→verify），DAG 失败重试 + 死信队列落地。
2. 工具级并行度自适应（CPU/带宽感知）+ 子进程复用（nuclei/ffuf 单实例多目标批处理）。
3. 中间结果流式传递（不等全量完成即启动下游），缩短端到端时延。
4. 引擎早停（某引擎连续 N 次 0 命中且低风险，降优先级或跳过）。

### D20. 缓存 / 去重 / 早停
**现状缺陷**：ffuf 增量缓存（P1-1 待办）、LLM 语义缓存（P1-2 待办）均未落地，重复扫描全量重算。

**优化小点**：
1. ffuf 增量缓存（同目标同字典跳过）+ LLM prompt 语义缓存（相似判定复用）。
2. URL/参数去重（规范化 + 参数排序哈希），避免重复请求。
3. 引擎级缓存（带外域名/指纹/技术栈短期复用，减少重复探测）。
4. 全局早停（命中关键 Critical 即可提前收束深度，节省 token 与时间）。
